# 六爻网页架构设计

## 目标

项目目标不是只做一个“掷硬币页面”，而是做一个可扩展的六爻起卦与结构化解读系统，支持移动端和 PC。

首版重点：

- 流程完整
- 数据接口稳定
- 展示层可扩展
- 正式卦库未完成时仍可开发

## 产品流程

1. 用户输入问题
2. 用户手动掷六次铜钱
3. 系统记录每次三枚铜钱结果
4. 系统生成六爻结果
5. 系统推导本卦、变卦、动爻
6. 系统输出结构化解读
7. 用户查看基础含义与扩展说明

## 页面分层

### 1. 起卦输入层

- 文本输入
- 语音输入按钮
- 示例问题入口

### 2. 投掷交互层

- 三枚铜钱动画
- 当前投掷进度
- 六次历史结果
- 重置起卦

### 3. 结果结构层

- 本卦
- 变卦
- 动爻
- 阴阳分布
- 上下卦编码

### 4. 解读层

- 基础解读
- 卦辞与象曰
- 动爻提示
- 断卦要点
- 扩展知识
- AI 个性化解读

## 推荐工程分层

- `src/components`
  UI 组件
- `src/lib`
  纯计算逻辑，包括投掷、爻生成、卦编码、规则组合
- `src/types`
  数据结构定义
- `src/data`
  本地 mock 数据与后续正式数据适配层
- `server`
  服务端代理与大模型调用

## 正式数据接入建议

不要让前端组件直接读取原始 JSON。应先做一层 adapter，把原始资料整理为统一结构后再进入页面。

建议分三层：

1. raw data
   原始 JSON 文件
2. normalized data
   统一字段与命名后的程序数据
3. presentation model
   直接给组件渲染的数据

## 当前已完成的程序边界

- 已支持六次投掷
- 已支持 6/7/8/9 转换为老阴、少阳、少阴、老阳
- 已支持动爻识别
- 已支持本卦/变卦编码生成
- 已支持结构化展示占位
- 已支持通过服务端代理调用 DeepSeek 生成个性化解读

## 待接入能力

- 64 卦名称与编码映射
- 卦宫信息
- 世应
- 六亲
- 六神
- 用神与断卦规则
- 卦辞、爻辞、象曰
- 针对不同问题类型的解读分支
- 正式卦库参与 AI 提示词拼装

## 风险点

- 原始 JSON 格式目前并不统一
- 部分字段命名存在“一爻/初爻”并存问题
- 部分卦象字符可能录入有误
- 详解数据当前覆盖率不足

## 实施顺序

1. 先稳定 schema
2. 再做 data adapter
3. 再接正式解卦数据
4. 最后精修动画与语音输入
